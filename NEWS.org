** v1.3.7 (2026-11-26)

The pinned channel carries the dokgen that folds each definition's source
behind a panel the reader opens.  Nothing in the parser, the renderers or the
JSON tree changes.

*** Changed

- The pinned Guix channel carries `guile-dokgen` 0.12.0: the published API reference folds the source behind each definition into a panel a reader opens, and reads on a quieter page with translucent surfaces.

** v1.3.3 (2026-11-21)

The API reference is rendered with Texinfo 7.3, so dokgen's stylesheet applies
and the page reads as cards with an index and a filter.  Nothing in the parser,
the renderers or the JSON tree changes.

*** Changed

- `manifest.scm` names `(specification->package "texinfo")` rather than the
  bare `texinfo` binding, which selected 6.8.  `texi2any` therefore emits the
  7.x definition structure (`def-block`, `def-line`, `def-name`), the structure
  `dokgen.css` styles.
- `channels.scm` pins the jointhefreeworld revision `24db897`, which carries
  `guile-dokgen` 0.9.2.

** v1.3.2 (2026-11-21)

The README's API links name the page the reference is, and the pinned channel
carries the dokgen that writes it.  Nothing in the parser, the renderers or the
JSON tree changes.

*** Changed

- The two README links to the reference read
  `https://jointhefreeworld.org/api-docs/orgwebalchemy/index.html`, the one page
  `maak docs` writes, rather than `API.html`.
- `channels.scm` pins the jointhefreeworld revision `dc9f38c`, which carries
  `guile-dokgen` 0.9.1.

** v1.3.1 (2026-11-21)

The API reference is generated by guile-dokgen, and the pipeline the renderers
share is drawn where it is described.  Nothing in the parser, the renderers or
the JSON tree changes.

*** Changed

- `maak docs` runs guile-dokgen, not guile-documenta, and writes one page with
  the stylesheet, the script and the diagrams dokgen drew beside it, so the
  page's own links resolve.
- `channels.scm` pins Guix master `5cea8de` and the jointhefreeworld revision
  `139880f`, which is where `guile-dokgen` comes from, so the Guix revision and
  the collection are pinned together; `manifest.scm` takes dokgen from there.
- The three stages — grammar, AST, renderers — are a mermaid diagram in the
  README and in the Commentary of `(orgwebalchemy peg)`, with its source and SVG
  under `resources/diagrams/` and a `maak diagrams` task that renders them.
- `(orgwebalchemy peg)`'s Commentary says that the module knows the language and
  the renderers know the output, and that links, figures and named elements are
  classified once so the renderers cannot disagree about a target.

** v1.3.0 (2026-11-20)

MIT, GitHub, and the two features that turn the AST into an interface.

*** License

- The library and its documentation are MIT, not LGPL-3.0-or-later and
  FDL-1.3-or-later.  =COPYING= becomes =LICENSE=, every source header and recipe
  carries =SPDX-License-Identifier: MIT=, and the packaging metadata, the
  container label and the README name the new licence.  Nothing in the code, the
  build or the tests changes; a site that embeds the library stops inheriting an
  obligation it did not ask for.
- Breaking for anyone who reads the licence metadata: =LGPL-3.0-or-later= and
  =FDL-1.3-or-later= are both gone, and =MIT= covers the code and the
  documentation alike.

*** Added

- =link-protocols=, a parameter holding an alist of protocol symbols and
  resolver procedures, so a host application resolves =[[yt:...]]= and
  =[[zotero:...]]= itself: a resolver takes the path and returns the href to
  use, or =#f= to leave the target as the document wrote it.  =org-link-href=
  asks the registry first, so one binding serves both renderers, and the parser
  still learns no scheme it does not resolve itself.
- =(orgwebalchemy json)=: =org->json=, =org-ast->json=, =inline-org->json= and
  =json-string=.  A document is always an array of nodes, a node is always
  ={"type": ..., "children": [...]}=, and prose is resolved to the inline nodes
  the renderers see.  Guile's standard library has no JSON writer, so the
  library writes it, and the runtime dependency on Guile alone is unchanged.
- The node vocabulary, block and inline, documented in the README with the
  children each node carries.
- A JSON snapshot of the whole feature fixture, compared on every test run.

*** Changed

- =org-link-display= states what a resolver does: it changes the href, never the
  text a link shows, because =[[yt:dQw4w9WgXcQ]]= says exactly that and the
  resolution belongs in the attribute.
- The README names four modules rather than three, and its quick-reference
  table, module map and API overview carry the new one.

*** Packaging

- The dev manifest pins Veritas v1.4.5, from GitHub rather than the old forge.
- CI moves from Woodpecker to GitHub Actions: =ci.yml= calls the shared Byggsteg
  workflow with the same =maak-test= and =maak-deploy= tasks, and
  =.woodpecker/= is gone.
- Veritas collected 48 suites, 244 tests and 378 assertions at this release.
